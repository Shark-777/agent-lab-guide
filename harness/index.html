Критерии готовности

    Журнал работы

    1. Здесь появятся наблюдения, действия и результаты.

    Память между сессиями

    Следующая сессия получает сохранённую цель, наблюдения, изменения и следующий шаг. Свежий контекст сам по себе не сохраняет память.

    

    Конструктор рабочей системы
    Меняй состав и запускай тот же сценарий снова. Это конфигурация учебной модели: реальные сервисы не подключаются.
    Контекст и методики
    Действия и обратная связь
    MCP не обязателен для каждой задачи. Локальные файлы, CLI и тесты тоже могут быть инструментами. Коннектор даёт доступ к конкретному сервису; механизм подключения зависит от среды.
    Значения лимитов выбраны для тренажёра. В рабочей среде дополнительно задают бюджет времени и стоимости, границы доступа и условия обращения к человеку.
    Что ты собираешь
    Задача + модель + контекст + доступные действия + проверка + управление продолжением.
    Правило продолжения
    Неудача → получить конкретную ошибку → изменить гипотезу или действие → проверить снова. Если нет доступа, не хватает решения владельца или исчерпан лимит — сохранить прогресс и показать точный блокер.
    Выход для реальной настройки
    Экспортируй состав и рабочий договор. Они служат основой настройки агента, но не устанавливают MCP и не создают работающий планировщик автоматически.

    От идеи до приложения
    Требования продукта → спецификация поведения → небольшие задачи с критериями → выполнение каждой задачи с обратной связью → проверка связанного поведения → сохранение прогресса → следующая задача.
    Для новой функции сначала определяют поведение; для бага сначала воспроизводят ошибку. Цикл внутри задачи может повторяться, а проектный прогресс сохраняется между задачами. Отдельный Inspector — выбранная нами архитектура, а не обязательная часть любого агента.

    Источники и границы модели
    Этот тренажёр — авторская учебная модель, а не воспроизведение конкретного продукта. Все события симулятора вымышлены; схема не гарантирует, что любая реальная задача будет решена автономно. Автономность требует доступов, полезной обратной связи и условий остановки.
    • Anthropic: Building effective agents — различие агентов и заранее заданных workflows.
    • Anthropic: Effective harnesses for long-running agents — работа между сессиями и сохранение прогресса.
    • Anthropic: Agent Skills — инструкции, ресурсы и скрипты, загружаемые по задаче.
    • Model Context Protocol: Architecture overview — протокол подключения возможностей, а не управление агентным циклом.
